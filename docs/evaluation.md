# Evaluation

All numbers below were produced by `scripts/train_risk_model.py` on the
fully synthetic cohort and are committed in `docs/evaluation.json`. Nothing
here uses real patient data.

## TwinRisk v1 — 48-hour deterioration prediction

**Task.** Given a patient-day of assimilated wearable/CGM summaries (with
personal baselines from the prior 14 days only), predict whether an
**infection-like acute deterioration** begins within the next 48 hours.
Abrupt events (hypertensive crisis, severe hypoglycaemia) are deliberately
*excluded* from this learned task — they carry no wearable-detectable
prodrome and are handled by the live monitoring-alarm layer
(absolute thresholds, NEWS2).

**Cohort.** 120 synthetic patients × 180 days (archetype mixture:
T2D+hypertension, prediabetes+stress, elderly post-cardiac, COPD, insulin-
treated T2D, OSA, healthy). Event schedule drawn by the transparent hazard
model. Split **by patient** (96 train / 24 validation) — no patient leakage.

| Metric (validation) | Value |
|---|---|
| Patients / patient-days (val) | 24 / 3,984 |
| Positive days (acute onset ≤ 48 h) | 66 (1.7 %) |
| **AUROC** | **0.784** |
| **Average precision** | **0.493** (≈ 30× prevalence) |
| Operating threshold | 0.01 |
| Sensitivity at threshold | 0.697 |
| Specificity at threshold | 0.765 |
| Alerts per patient-day | 0.24 |
| **Mean lead time when detected** | **≈ 18.5 h before acute onset** |
| Events detected (val) | 46 |

ROC sweep (validation):

| Threshold | Sensitivity | Specificity |
|---|---|---|
| 0.005 | 0.85 | 0.55 |
| 0.01 | **0.70** | **0.77** |
| 0.02 | 0.55 | 0.88 |
| 0.05 | 0.42 | 0.94 |
| 0.10 | 0.32 | 0.97 |

The deployed threshold (0.01) trades a false-alarm rate of ~1 alert per 4
patient-days for ~70 % sensitivity — a deliberate operating point for a
clinical early-warning tool where misses dominate the cost. The ROC sweep is
committed so the panel can read the full trade-off.

## Assimilation accuracy (mirror fidelity)

Compared against simulator ground truth on 30-day synthetic streams:

| Channel | MAE vs truth | Sensor noise floor |
|---|---|---|
| Heart rate | ≈ 3.7 bpm | σ 3.5 bpm |
| CGM glucose | ≈ 3.0 mg/dL | σ 2.5 mg/dL |
| SBP (model-carried, cuff-corrected) | ≈ 5.1 mmHg | cuff σ 4 mmHg |

The assimilated state sits at the sensor noise floor — the filters recover
the physiological trajectory without lagging behind behaviour transitions.

## Protocol engine behavioural checks (pytest)

- Lifestyle protocol (9,000 steps + −300 kcal + 150 g carbs) on the T2D
  archetype: HbA1c 7.52 % → 6.90 %, weight −3.5 kg in 90 days — DPP-magnitude
  effects.
- Metformin dose–response: 0 / 1000 / 3000 mg → HbA1c 7.86 / 7.52 / 7.16 %.
- Goal-seek: smallest metformin dose reaching 7.0 % on the lifestyle base,
  with a ±10 % physiology jitter band.
- NEWS2 implementation reproduces the RCP table at boundaries (unit tests).
- Full physiological determinism for a fixed seed.

Run everything: `python -m pytest tests/ -q`.

## Threats to validity (read this)

- **All data is synthetic**, generated by the same forward model the twin
  uses. Evaluation therefore measures *internal consistency* (can the risk
  layer read the physiology layer's prodromes through realistic sensor
  noise and personal baselines?), **not** clinical validity.
- No class-imbalance tricks, no threshold peeking on test patients, and the
  split is by patient — but the true test is prospective validation on real
  cohorts (e.g., MIMIC-IV waveforms + wards, or a wearable cohort with
  infection labels), which is the first roadmap item.
- The 0.493 average precision should be read against the 1.7 % prevalence
  (baseline AP = 0.017): the model concentrates risk ≈ 30× above the base
  rate in its top-ranked days.
